# CLI and operations

> The commands, keys, configuration and diagnostics you use Kubic through.
> Package internals live on the [packages pages](../packages/README.md).

Examples write `kubic`, the command `npm install -g kubic` puts on your `PATH`
(see [install](../getting-started.md#install)). Every command answers
`--help`, and [commands](commands.md) lists the rules they all follow.

- [commands.md](commands.md): the command index and the rules every command follows
- [run.md](run.md): `kubic run`, `attach` and `resume`
- [tui.md](tui.md): `kubic tui`, with its [keys](tui-keys.md) and [approvals](approvals.md)
- [sessions.md](sessions.md): `kubic sessions`
- [journal.md](journal.md): `kubic diff`, `undo`, `log`, `status`, `git`, `commit` and `journal prune`
- [models.md](models.md): `kubic models`, `setup` and `keys`, `models.json` and provider keys
- [analysis.md](analysis.md): `kubic cost`, `eval`, `benchmark`, `replay`, `export`, `policy` and `audit`
- [exit-codes.md](exit-codes.md): the exit codes
- [tools.md](tools.md): the tools the model calls, their arguments and results
- [configuration.md](configuration.md): config layers, keys and `kubic config`
- [enterprise.md](enterprise.md): managed policy, audit, spend caps, the bash sandbox and corporate networks
- [github-action.md](github-action.md): Kubic in a GitHub workflow
- [trust.md](trust.md): `kubic trust` and the project-trust store
- [doctor-and-debug.md](doctor-and-debug.md): `kubic doctor` and debugging
- [skills.md](skills.md): `kubic skills`, which skills loaded and why any were left out
